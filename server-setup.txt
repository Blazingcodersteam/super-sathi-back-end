Supersathi Staging — Deployment & PM2 Setup

Important: Commands are intended to be run from the SSH user staging-supersathi-node.
sudo commands at the end must be executed by a user with root/sudo permission.

1. SSH login
ssh staging-supersathi-node@YOUR_SERVER_IP

Check:

whoami
pwd

Expected user:

staging-supersathi-node
2. Go to project directory
cd ~/htdocs/staging.supersathi.com/super-sathi-web

Verify:

pwd
ls
3. Install NVM

If NVM is not already installed:

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash

Reload shell:

export NVM_DIR="$HOME/.nvm"
[ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"

Verify:

nvm --version

Expected:

0.40.3
4. Install Node.js 20
nvm install 20
nvm use 20
nvm alias default 20

Verify:

node -v
npm -v
which node
which npm

Expected approximately:

Node: v20.x.x
npm: 10.x.x
5. Install project dependencies

From the project directory:

cd ~/htdocs/staging.supersathi.com/super-sathi-web

Then:

npm ci

Use npm ci when package-lock.json is available.
Do not use npm audit fix or npm audit fix --force during this deployment unless dependency upgrades are specifically planned and tested.

6. Verify environment configuration

Do not print the .env values because it contains secrets.

Only verify that the required configuration exists:

grep -E '^(PORT|EMAIL_OUTBOX_)' .env

Expected:

PORT=9000
EMAIL_OUTBOX_MAX_ATTEMPTS=5
EMAIL_OUTBOX_BASE_BACKOFF_MS=60000
EMAIL_OUTBOX_POLL_INTERVAL_MS=2000
EMAIL_OUTBOX_BATCH_SIZE=5
EMAIL_OUTBOX_SENT_RETENTION_DAYS=30
EMAIL_OUTBOX_CLEANUP_INTERVAL_MS=3600000
EMAIL_OUTBOX_CLEANUP_BATCH_SIZE=500
EMAIL_OUTBOX_PROCESSING_TIMEOUT_MS=900000
7. Build the project
npm run build

Expected:

Process exited with code 0

No TypeScript compilation errors should be present.

8. Test the API before PM2

Run:

npm start

Verify from another SSH terminal:

curl -i http://127.0.0.1:9000/health

Expected:

HTTP/1.1 200 OK

with:

{"status":"ok", ...}

After verification, stop the foreground process:

Ctrl + C

Do not run server-start.sh, because the existing script contains pkill -f "node src/app.js" and can terminate an existing Node process.

9. Install PM2

Install PM2 for the current SSH user:

npm install -g pm2

Verify:

pm2 -v
10. Start Supersathi API using PM2

From:

cd ~/htdocs/staging.supersathi.com/super-sathi-web

Start:

pm2 start src/app.js --name supersathi-staging

Check:

pm2 status

Expected:

supersathi-staging    online

Check port:

ss -ltnp | grep ':9000'

Test:

curl -i http://127.0.0.1:9000/health
11. Setup Email Outbox Worker

First verify that the worker exists:

ls -l src/workers/emailOutboxWorker.js

Check package script:

cat package.json | grep -A5 -B5 "worker:email-outbox"

Expected:

"worker:email-outbox": "node src/workers/emailOutboxWorker.js"
12. Test Email Outbox Worker manually
npm run worker:email-outbox

Expected logs should contain something similar to:

Database pool created successfully

[EMAIL-OUTBOX-WORKER] ready
poll_interval_ms=2000
batch_size=5
max_attempts=5
...

Database connected as id XXXXX

[EMAIL-OUTBOX-WORKER] cleanup result reason=startup deleted_sent=0

If successful, stop it:

Ctrl + C
13. Start Email Outbox Worker with PM2
pm2 start src/workers/emailOutboxWorker.js --name supersathi-email-outbox-worker

Check:

pm2 status

Expected:

supersathi-staging
        online

supersathi-email-outbox-worker
        online
14. Check Email Outbox Worker logs
pm2 logs supersathi-email-outbox-worker --lines 50

Verify:

Database pool created successfully
Database connected as id XXXXX
[EMAIL-OUTBOX-WORKER] ready ...

Also check the error log:

pm2 logs supersathi-email-outbox-worker --err --lines 50

There should be no startup/database errors.

15. Save PM2 process list

Once both processes are confirmed healthy:

pm2 save

Expected:

[PM2] Successfully saved in .../.pm2/dump.pm2

Verify:

pm2 status
16. Configure PM2 auto-start after server reboot

This step requires sudo/root access.

Run:

pm2 startup

PM2 will display a command similar to:

sudo env PATH=$PATH:/home/staging-supersathi-node/.nvm/versions/node/v20.20.2/bin /home/staging-supersathi-node/.nvm/versions/node/v20.20.2/lib/node_modules/pm2/bin/pm2 startup systemd -u staging-supersathi-node --hp /home/staging-supersathi-node
IMPORTANT

The exact command generated by pm2 startup should be used.

A user with sudo/root permission must execute that command:

sudo env PATH=$PATH:/home/staging-supersathi-node/.nvm/versions/node/v20.20.2/bin /home/staging-supersathi-node/.nvm/versions/node/v20.20.2/lib/node_modules/pm2/bin/pm2 startup systemd -u staging-supersathi-node --hp /home/staging-supersathi-node

Then login again as:

staging-supersathi-node

and run:

pm2 save
17. Final verification
pm2 status

Expected:

┌────┬───────────────────────────────────┬─────────┐
│ id │ name                              │ status  │
├────┼───────────────────────────────────┼─────────┤
│ 0  │ supersathi-staging                │ online  │
│ 1  │ supersathi-email-outbox-worker    │ online  │
└────┴───────────────────────────────────┴─────────┘

API:

curl -i http://127.0.0.1:9000/health

Public API:

https://staging.supersathi.com/health

Worker:

pm2 logs supersathi-email-outbox-worker --lines 30
After future project uploads

If only application code changed:

cd ~/htdocs/staging.supersathi.com/super-sathi-web

pm2 restart supersathi-staging
pm2 restart supersathi-email-outbox-worker

pm2 status

If package.json or package-lock.json changed:

npm ci

then:

pm2 restart supersathi-staging
pm2 restart supersathi-email-outbox-worker

Finally:

pm2 save
One important rule

Do not run this during normal deployment:

./server-start.sh

because the current script contains:

pkill -f "node src/app.js"

which can kill the running API process.
